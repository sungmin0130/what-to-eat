# 오늘 뭐 먹지? — 내 주변 메뉴 돌림판 (PRD)

## 1. 앱 개요
- 한 줄 소개: 내 위치 근처 음식점을 찾아 대표 메뉴로 돌림판을 만들고, 돌려서 오늘 먹을 메뉴를 정한다.
- 해결할 문제: "뭐 먹지?" 고민에 시간이 오래 걸리고, 여럿이 있으면 정하기가 더 어렵다.
- 사용자: 점심·저녁 메뉴를 빨리 정하고 싶은 학생, 친구들과 함께 고르는 사람
- 목표
  - 앱을 열고 30초 안에 메뉴를 정한다
  - 실제로 근처에 있는 음식점의 메뉴만 나온다
- 하지 않는 것 (이번 범위 밖): 음식 주문·결제, 리뷰 쓰기, 회원가입

## 2. 사용자와 권한
| 누구 | 할 수 있는 것 |
|---|---|
| 모든 사용자 (로그인 없음) | 위치 허용, 음식점 찾기, 돌림판 만들기·돌리기, 결과 보기 |

- 회원가입 없이 누구나 바로 쓴다. 개인 설정(제외 메뉴, 최근 결과)은 그 기기의 브라우저에만 저장한다.

## 3. 사용 흐름
1. 앱을 연다 → 검색 거리를 정한다 (기본 500m, 슬라이더나 빠른 버튼) → [내 주변 찾기]를 누른다
2. 브라우저가 위치 권한을 묻는다 → 허용
3. 서버가 내 위치에서 정한 거리 안의 음식점을 찾는다
4. 음식점마다 대표 메뉴를 정하고, 메뉴 목록을 보여 준다
5. 빼고 싶은 메뉴를 끄고, 원하면 직접 메뉴를 넣는다
6. [돌리기]를 누른다 → 돌림판이 돌다가 멈춘다
7. 결과 화면: 메뉴 이름, 그 메뉴를 파는 근처 음식점, 거리, [지도에서 보기]

## 4. 기능 정의서
| 번호 | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F1 | 내 위치 가져오기 | 브라우저 위치 기능(Geolocation)으로 위도·경도를 받는다 | 필수 |
| F2 | 주소로 위치 정하기 | 위치를 허용하지 않거나 실패하면 동네 이름·주소를 입력해서 찾는다 | 필수 |
| F3 | 주변 음식점 찾기 | 카카오 로컬 API(카테고리 `FD6` 음식점)로 정한 거리 안 음식점을 거리순으로 가져온다. 넓은 거리는 구역을 나눠 찾아 먼 곳까지 골고루 가져온다 (최대 300곳) | 필수 |
| F4 | 검색 거리 정하기 | 내 위치에서 얼마나 먼 곳까지 찾을지 정한다. 슬라이더로 100m~3km(100m 단위)를 고르고, 빠른 버튼(300m / 500m / 1km / 2km)도 있다. 고른 거리 옆에 걸어서 걸리는 시간(분당 80m 기준, 예: "500m · 걸어서 약 6분")을 보여 준다 | 필수 |
| F4-1 | 거리 바꿔 다시 찾기 | 메뉴 고르기 화면에서도 거리를 바꿀 수 있다. 바꾸면 위치를 다시 묻지 않고 같은 위치로 다시 찾는다 | 필수 |
| F4-2 | 거리 기억하기 | 마지막으로 고른 거리를 이 기기에 저장해, 다음에 열면 그 거리로 시작한다 | 선택 |
| F5 | 대표 메뉴 정하기 | 음식점 종류(예: `한식 > 국밥`)를 보고 정해 둔 표에서 대표 메뉴를 고른다 (6번 참고) | 필수 |
| F6 | 메뉴 목록 정리 | 같은 메뉴는 하나로 합치고, 메뉴마다 파는 음식점 수를 보여 준다 | 필수 |
| F7 | 메뉴 빼기·넣기 | 메뉴를 체크로 끄고 켠다. 직접 메뉴를 써서 넣을 수 있다 | 필수 |
| F8 | 돌림판 | 켜 둔 메뉴로 칸을 나눈 돌림판을 그리고, 버튼을 누르면 돌다가 무작위 칸에서 멈춘다 | 필수 |
| F9 | 결과 보기 | 뽑힌 메뉴와, 그 메뉴를 파는 근처 음식점(이름·거리·카카오맵 링크)을 보여 준다 | 필수 |
| F10 | 다시 돌리기 | 결과가 마음에 안 들면 바로 다시 돌린다. 방금 나온 메뉴를 빼고 돌리는 것도 고를 수 있다 | 필수 |
| F11 | 종류로 거르기 | 한식·중식·일식·양식·분식·패스트푸드 등 종류별로 켜고 끈다 | 선택 |
| F12 | 최근 결과 | 최근에 뽑힌 메뉴 5개를 이 기기에 저장해 보여 준다 | 선택 |
| F13 | 결과 공유 | 결과를 링크 복사·공유하기(Web Share)로 친구에게 보낸다 | 선택 |

## 5. 화면
1. 시작 화면
   - 제목, 한 줄 설명
   - 검색 거리: "📏 500m · 걸어서 약 6분" 글자 + 슬라이더(100m~3km) + 빠른 버튼 [300m] [500m] [1km] [2km]
   - [내 주변에서 찾기] 버튼
   - [주소로 찾기] 입력칸 (위치를 허용하지 않을 때)
2. 메뉴 고르기 화면
   - 위: 지금 위치(동네 이름), 검색 거리, 찾은 음식점 수
   - 거리 바꾸기: 빠른 버튼 [300m] [500m] [1km] [2km] — 누르면 같은 위치로 바로 다시 찾는다
   - 메뉴 목록: 메뉴 이름 + 음식점 수 + 켜기/끄기
   - [+ 메뉴 직접 넣기]
   - [돌림판 만들기]
3. 돌림판 화면
   - 가운데: 돌림판 (칸마다 다른 색, 메뉴 이름), 위쪽에 화살표
   - 아래: [돌리기]
4. 결과 화면 (돌림판 위에 뜨는 창)
   - "오늘의 메뉴" + 메뉴 이름을 크게
   - 이 메뉴를 파는 근처 음식점 목록 (가까운 순, 이름·거리·[지도에서 보기])
   - [다시 돌리기] [메뉴 다시 고르기]
- 디자인: 아이보리 바탕·흰 카드·먹색 글자·금색 포인트만 쓰는 차분하고 깔끔한 모양. 돌림판 칸은 밝고 차분한 색. 결과 창은 폰에서는 아래에서 올라오는 창으로 보인다.
- 폰에서 한 손으로 쓰기 편하게 세로 화면을 기준으로 만든다. PC에서도 가운데 정렬로 보인다.

## 6. 대표 메뉴 정하는 방법
- 카카오 로컬 API는 음식점 이름·종류·주소·거리·전화번호·지도 링크를 주지만 **메뉴 정보는 주지 않는다.**
- 그래서 음식점 종류(`category_name`)의 마지막 칸을 보고, 미리 만든 "종류 → 대표 메뉴" 표에서 메뉴를 고른다.

| 음식점 종류 (예시) | 대표 메뉴 |
|---|---|
| 한식 > 국밥 | 국밥 |
| 한식 > 육류,고기 > 삼겹살 | 삼겹살 |
| 한식 > 찌개,전골 | 김치찌개 |
| 중식 > 중화요리 | 짜장면, 짬뽕 |
| 일식 > 초밥,롤 | 초밥 |
| 일식 > 돈까스,우동 | 돈까스 |
| 분식 | 떡볶이, 김밥 |
| 양식 > 피자 | 피자 |
| 양식 > 햄버거 / 패스트푸드 | 햄버거 |
| 치킨 | 치킨 |
| 아시아음식 > 베트남음식 | 쌀국수 |

- 표에서 찾을 때는 뒤 칸부터 본다. 마지막 칸이 가게 브랜드면(예: `치킨 > BHC치킨`) 앞 칸(치킨)으로 정한다. `한식`처럼 넓은 종류는 더 자세한 칸이 없을 때만 쓴다.
- 표에 없는 종류는 음식 종류 칸을 그대로 메뉴로 쓴다 (예: `한식 > 순대 > ○○순대` → 순대, `샐러드 > ○○샐러드` → 샐러드). 가게 브랜드 칸은 쓰지 않는다.
- 표는 서버 코드 안의 사전(dict)으로 두고, 나중에 쉽게 늘릴 수 있게 한다.
- 사용자는 메뉴 고르기 화면에서 잘못된 메뉴를 끄거나 직접 고칠 수 있다.

## 7. 규칙과 예외 상황
- 위치
  - 위치 기능은 https에서만 동작한다 (공개 주소가 https라 괜찮다).
  - 위치를 거부하거나 10초 안에 못 받으면 "주소로 찾기"를 안내한다.
  - 위치 좌표는 검색에만 쓰고 서버에 저장하지 않는다. 거리를 바꿔 다시 찾을 때 쓰도록 브라우저 메모리에만 잠깐 들고 있는다 (새로고침하면 사라진다).
- 검색 거리
  - 100m~3000m, 100m 단위만 받는다. 서버도 이 범위를 다시 확인하고, 벗어나면 가장 가까운 허용 값으로 맞춘다.
  - 카카오 API는 한 번에 "가까운 45곳"만 준다. 그래서 300m보다 넓은 거리는 원을 바둑판처럼 최대 16구역으로 나눠 구역마다 따로 찾고, 합친 뒤 같은 가게는 하나로 한다. 이렇게 해서 먼 곳의 가게도 골고루 나오게 한다 (최대 300곳). 그래도 다 못 가져오면 "일부만 골고루 보여요" 안내를 한다.
  - 거리는 내 위치에서 가게까지 직접 계산하고, 정한 거리보다 먼 가게는 뺀다.
  - 거리를 빠르게 여러 번 바꾸면 마지막으로 고른 거리의 결과만 보여 준다 (앞선 요청 결과는 버린다).
- 음식점 찾기
  - 카카오 API 키는 `.env`의 `KAKAO_REST_API_KEY`에 두고 서버에서만 쓴다. 브라우저는 우리 서버의 `/api/places`를 부르고, 서버가 카카오에 대신 요청한다 (키가 밖으로 드러나지 않게).
  - 정한 거리 안에 음식점이 하나도 없으면 "거리를 넓혀 보세요"와 함께 한 단계 넓은 거리 버튼(예: 300m → [500m로 다시 찾기])을 보여 준다.
  - 카카오 API가 실패하거나 느리면(5초) "잠시 후 다시 시도해 주세요"를 보여 준다.
  - 같은 위치(소수점 3자리)·반경의 검색 결과는 10분 동안 서버에 캐시해 API 호출을 줄인다.
  - 한 사람이 너무 자주 검색하지 못하게 1분에 10번으로 제한한다.
- 돌림판
  - 켜진 메뉴가 2개 이상이어야 돌릴 수 있다. 1개면 바로 그 메뉴가 결과다. 0개면 버튼을 막는다.
  - 칸 수에는 제한이 없다. 켜 둔 메뉴를 모두 넣는다. 칸이 많아지면 메뉴 이름 글자를 칸 너비에 맞게 작게 하고, 길면 끝을 "…"로 줄인다. 30칸이 넘으면 "칸이 좁으면 이름이 작게 보여요" 안내를 한다.
  - 맞닿은 칸은 같은 색이 되지 않게 한다.
  - 결과는 칸 크기와 상관없이 메뉴마다 같은 확률로 뽑는다. 돌림판이 멈추는 자리와 결과가 항상 같아야 한다.
  - 돌아가는 동안에는 [돌리기]를 다시 누를 수 없다.
- 입력
  - 직접 넣는 메뉴 이름은 1~15자, 같은 이름은 넣지 않는다.
  - 메뉴·음식점 이름은 글자 그대로 보여 준다 (HTML 태그가 실행되지 않게).
- 작품 규정
  - 음식점 상호·로고 그림을 따로 가져와 쓰지 않는다. 그림은 이모지와 직접 만든 것만 쓴다.

## 8. 저장할 데이터
- 서버 (SQLite `app.db`)
  - 검색 캐시: 위치 키(위도·경도 소수점 3자리), 반경, 결과 JSON, 저장 시각 — 10분 지나면 지운다
  - 대표 메뉴 표: 코드 안 사전으로 둔다 (DB 아님)
- 브라우저 (localStorage)
  - 내가 끈 메뉴, 직접 넣은 메뉴
  - 최근 결과 5개 (메뉴 이름, 뽑은 시각)
  - 마지막으로 고른 검색 거리
- 개인정보는 저장하지 않는다 (회원 없음, 위치 저장 안 함).

## 9. 기술 구성
- 서버: Flask (`app.py`), SQLite, requests로 카카오 로컬 API 호출, flask-limiter로 요청 수 제한
- 화면: HTML + CSS + 자바스크립트, 돌림판은 `<canvas>`로 그린다
- API
  - `GET /` — 화면
  - `GET /api/places?lat=&lng=&radius=` — 주변 음식점 + 대표 메뉴 목록 (`radius`는 미터, 100~3000)
  - `GET /api/geocode?query=` — 주소·동네 이름을 좌표로 바꾸기 (카카오 키워드 검색)
- 비밀값: `.env`의 `KAKAO_REST_API_KEY` (카카오 디벨로퍼스에서 직접 발급)
- 시각은 한국 시간(Asia/Seoul)으로 보여 준다.

## 10. 완료 기준
- 폰에서 공개 주소를 열고 위치를 허용하면, 근처 음식점의 메뉴로 돌림판이 만들어진다
- 위치를 거부해도 동네 이름을 넣으면 같은 일을 할 수 있다
- 검색 거리를 바꾸면 그 거리 안의 음식점만 나오고, 모든 음식점의 거리가 정한 거리 이하다
- 메뉴 고르기 화면에서 거리를 바꾸면 위치를 다시 묻지 않고 새 결과가 나온다
- 돌림판이 멈춘 칸의 메뉴와 결과 창의 메뉴가 항상 같다
- 결과 창에서 그 메뉴를 파는 실제 근처 음식점과 카카오맵 링크가 나온다
- 메뉴를 끄면 돌림판에서 빠지고, 직접 넣은 메뉴는 돌림판에 들어간다
- 브라우저 개발자 도구에서 봐도 카카오 API 키가 보이지 않는다
- 반경 안에 음식점이 없거나 API가 실패해도 앱이 멈추지 않고 안내 문구가 나온다
